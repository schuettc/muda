## Symptom

Jobs queue while self-hosted runners boot, register offline and are reaped idle;
the provider status page remains green.

## Detect

```sh
muda measure
muda notices
muda logs 12345
```

Use a real run ID instead of example 12345. Compare queue age with the baseline,
runner retirement notices, baked versions, launcher logs and capacity errors.
Jobs that never started need runner-plane evidence, not an assumption that empty
job logs mean healthy idleness.

## Fix

Give the baked runner version an owned gated refresh path, and alert on oldest
queue age, capacity rejection and launched-then-reaped-idle counts. Deploy the
runner plane from independent healthy capacity and observe a canary. Present the
operational plan for approval and ship it in a PR.

## Stacks

### github-actions

Before: self-hosted deployment requires the same failing plane and a helper
called “latest” returns a library default. After: name the default honestly,
refresh the exact runner pin through reviewed bump PRs, deploy from hosted
capacity and end with a canary proving the new runner accepts work.

### cdk

Before: immutable runner images never refresh and silence looks healthy.
After: wire alarms and a sweep that matches launcher classes exactly, paginates
within an explicit budget, flags truncation and reports telemetry absence.
Evaluate missing-data alarms over at least two sweep intervals.

## Traps

- Runner versions can expire within a rolling support window even when the
  provider reports no outage. A library default is not necessarily current.
- Jobs carry extra OS/architecture labels: reuse the launcher’s exact class
  matching rather than naive label equality.
- Newest-first, single-page listings omit the oldest jobs. Truncation is missing
  evidence, not a small queue.
- Missing-data-breaching alarms need at least two sweep intervals or interval
  changes can generate false pages; missing telemetry is not zero queue age.
- OIDC trust may use immutable subjects. Inspect the actual subject before
  writing exact-match trust conditions.
- Observe the first real canary (lesson 8): review cannot prove there is no daemon
  startup race or identity mismatch.

## Verify

```sh
muda compare --before 2026-09-01..2026-09-08 --after 2026-09-08..2026-09-15 --gates
muda record check
```

The dates above are example windows; replace them with representative before/after windows.
Compare queue p50/p90 and oldest-job age, inspect current runner versions, and
exercise rejected capacity and absent telemetry alarm paths. Prove the hosted
runner-plane deploy and real canary without removing deployment approvals.
Verify on the real PR pipeline and again after merge. The gate inventory must
remain the same or stronger; the user confirms the receipt.

## Evidence

Illustrative example only, not a measured adopter result: a 90-minute oldest queue age becomes 2 minutes, while refused capacity
and absent telemetry now produce visible alarms.
Record actual before/after measurements, coverage, tree/asset identities and
run/job/step sources in the finding receipt; never substitute these example numbers.
