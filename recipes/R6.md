## Symptom

Deploys build images under emulation, repeat builds per stage, and may ship an
image CI never tested.

## Detect

```sh
muda measure
muda scan
muda logs 12345
```

Run ID 12345 is an example. Read the measured image-build runs as well as deploy
runs. The agent correlates asset/input identity, build/push/skip outcomes, layer
hits and resolved digests across stages. Empty deploy logs cannot prove zero
builds, and configured cache flags cannot prove measured hits. W9 is inferred
from logs and code, not a stack-output parser in muda.

The cloud side settles a suspected finding: the image digests in each stage's
registry. When the logs do not show them, ask the human to run the registry's
read-only describe-images command for each stage and paste the output. Without
that output, the finding stays suspected. muda itself reads no cloud provider
and holds no cloud credentials.

## Fix

Build and smoke-test the actual artifact natively outside deploy, keyed by
stage-independent content identity. PR builds read cache without publishing;
trusted merge builds populate artifacts and cache. Deploy asserts availability
and promotes the tested artifact by digest, then checks running identity.
Approve the design and rollback plan; deliver one scoped PR at a time.

## Stacks

### github-actions

Before: each deploy builds and publishes an image. After: a native image
build job produces and tests it once, with a read-only PR cache and a trusted
merge cache writer. Required PR checks include image verification; deploy
waits on a fail-closed availability guard, and promotion compares digests.
Inspect both legacy branch protection and rulesets for required checks.

### cdk

Before: stage-specific assets rebuild inside deploy. After: test identity
equality across stages after replaying the actual CI pre-synth preparation
(including lock registry retargeting). Record digest references in IaC and
assert all expected artifacts exist before deploy. Update all generated-lock
readers and writers, including packaging and release.

### docker

Before: emulated builds, secret build arguments and no cache writer. After:
native builds for the target platform, secret mounts, dependency layers before
local source, and a mutable registry cache separate from immutable artifacts.
Merge writes cache; all builds read it. If splitting a lock by registry, test
disjoint sets whose union equals the export and reject ambiguous duplicates.
Check single-manifest media type for runtimes that reject indexes; disable
provenance/SBOM attachments only when required by that compatibility contract
and preserve security checks elsewhere.

### go

Before: every matrix leg cross-compiles every release target, although a pure-Go
build is host-independent: `CGO_ENABLED=0`, `-trimpath`, an explicit GOOS and
GOARCH and the same Go version produce the same artifact on any host, so all but
one leg duplicate the work. After: build the targets once on one leg and upload
them. Downloading them is optional, and only for legs that execute the binary
(smoke or integration tests); each such leg gains a `needs:` edge that
serializes it behind the build. Keep the build reproducible with a fixed
`-ldflags` stamp (a version from the tag, never a build time); `-buildvcs`
stamps the commit and a dirty-tree flag by default, so build from a clean
checkout of the same commit. Then compare artifact hashes between the tested
build and the released one before claiming "the tested artifact".

## Traps

- Fix the producing structure, not merely a missing cache (lesson 2).
- CI green does not prove the image works (lesson 4): build and smoke-test what ships.
- A registry copy can wrap a single manifest into an index and change digest.
  Where using buildx imagetools, evaluate `--prefer-index=false` and assert both
  digest and media type after copying.
- Authenticate separately to each registry; do not assume one cloud identity’s
  inspection API can read the destination. Only exact not-found means absent;
  permission, network and other errors must fail loudly.
- Cache-from alone never populates a cache. A configured cache is not a hit;
  distinguish a skipped existing artifact from reused build layers.
- Test the actual produced format, every write target’s mutability and CI’s real
  preparation, then observe the first real stage run deliberately (lesson 8).
- An immutable tag check is point-in-time, not eternal: tags can move if policy
  or ownership changes. Resolve and compare digests, including after deploy.
- Preflight tag/version/CHANGELOG uniqueness and publication collisions before
  irreversible infrastructure changes. An avoidable release collision must not
  strand a partially changed deployment.

## Verify

```sh
muda compare --before 2026-09-01..2026-09-08 --after 2026-09-08..2026-09-15 --gates
muda record check
```

The dates above are example windows; replace them with representative before/after windows.
Compare build and deploy critical paths separately. Prove one build per content
identity where intended, warm layer hits on repeat builds, correct media type,
stage hash equality and identical tested/promoted/running digests. Missing build
jobs remain unavailable evidence; never claim savings from empty deploy logs.
Verify on the real PR pipeline and again after merge. The gate inventory must
remain the same or stronger; the user confirms the receipt.

## Evidence

Illustrative example only, not a measured adopter result: deploy time drops from 27 minutes to 8 minutes; the deploy build step
drops from 840 seconds to a 15-second availability check. Separate build-job
evidence still accounts for artifact production and actual layer hits.
Record actual before/after measurements, coverage, tree/asset identities and
run/job/step sources in the finding receipt; never substitute these example numbers.
