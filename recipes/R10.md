## Symptom

Deploy actually repeats checks CI already executed on a proven identical tree;
the repeated checks dominate time before deployment.

## Detect

```sh
muda measure
muda scan
muda gates
muda logs 12345
```

Use a measured run ID instead of example 12345. Match applicable workflow
versions, commands, action refs/inputs, interpreter, lock, environment and
platform. Prove the checkout tree and target branch; a PR head is not necessarily
the tested merge-ref tree. Count only actually executed equivalent mirrors.
CI success plus deploy success with mirrored jobs skipped is not W6 duplication.
Static duplicate sets or missing filters/concurrency suggest investigation, not
automatic permission to cancel or omit work.

## Fix

After user confirmation of gates and tested-tree identity, record successful
complete CI checks by tree and target branch. Deploy reuses only authenticated,
unexpired proof of equivalent checks; otherwise it runs them. Retain every
check CI did not perform for the target. Deliver the guard as an approved PR.

## Stacks

### github-actions

Before: deploy always repeats all checks, or skips them solely because a PR
was green. After: CI’s final record job needs every check; deploy looks up
proof scoped to this repository, CI workflow, target branch, PR event, exact
tested tree, successful run and expiry. Only proven mirrors may skip. The
deploy gate requires successful lookup and each check either successful or
(skipped with validated proof), plus no cancellation. On lookup API errors,
emit a visible warning and run full checks; never fail open. Give status-read
permission only where needed.

### cdk

Before: tree reuse also removes production synth or production registry
resolution that CI never ran. After: list target-specific checks separately,
run them always (including production-stage synth and read-only dependency
resolution against the production registry), and verify their gate edges.

## Traps

- The same tree is not the same check (lesson 7). Keep production-specific
  checks and base-dependent configuration verification that CI never executed.
- Actually executed proven mirrors are the only saving. Skipped deploy checks
  already reused proof; do not count them as duplication or invent savings.
- A merge/squash/rebase may change the tested tree. Prove actual checkout-tree
  identity and up-to-date behavior; do not substitute commit labels.
- Scope proof to the target branch and retain literal ref guards that existing
  contract tests rely on. Renamed or expired records must miss safely and run
  full checks; unknown proof identity is not a pass.
- All readers and writers of a generated lock artifact, including release,
  must use the same preparation and dependency identity before reuse is safe.
- Exemptions on stable semantic IDs fail loudly if stale; never use step indices.
- Test the real guard and record paths in the first actual pipeline (lesson 8),
  including negative cases, instead of merely asserting the conditional text.

## Verify

```sh
muda compare --before 2026-09-01..2026-09-08 --after 2026-09-08..2026-09-15 --gates
muda record check
```

The dates above are example windows; replace them with representative before/after windows.
Compare only time saved by previously executed mirrors. Exercise exact-proof
hits, different trees/branches, expired or renamed proof, failed CI and lookup
errors; every miss runs full checks. Production-specific gates execute on every
deploy and the confirmed protection inventory remains intact.
Verify on the real PR pipeline and again after merge. The gate inventory must
remain the same or stronger; the user confirms the receipt.

## Evidence

Illustrative example only, not a measured adopter result: a 10-minute deploy becomes 4 minutes by reusing 6 minutes of proven
checks; production-specific checks still execute and skipped mirrors are not
counted as duplicate work in the next baseline.
Record actual before/after measurements, coverage, tree/asset identities and
run/job/step sources in the finding receipt; never substitute these example numbers.
